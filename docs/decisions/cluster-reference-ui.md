# 계기판 레퍼런스를 적용한 구간 안내 UI

사용자 제공 영상: https://www.youtube.com/shorts/WxQPv98HVO0
제목: 돈 주고 스마트센스 넣어야 하는 이유(자동 차선 변경)(고속도로 주행보조2), CARPAGO83.
2026-11-14 ego lite에서 실제 영상의 약4초/7초/10초 장면을 확인했다.

## 관찰과 설계

영상의 계기판은 밝은 아이스블루 배경에 멀어질수록 좁아지는 도로, 후면에서 본 차량, 녹색 차로 면 강조를 사용한다. 기존 앱의 평면 지도식 도식과 큰 분홍 리본을 이 구성을 참고한 원근 도로 장면으로 교체한다. 영상에 나오는 속도계나 실제 주변 차량·자동주행 상태는 우리 SDK로 확인되지 않았으므로 만들지 않는다. 원본 영상/그래픽을 앱에 복사하지 않고 Compose Canvas로 새로 그린다.

- 시선 순서: 하나의 안내 문장 → 연결까지 거리 → 도로와 차량. 전체 앱에서는 텍스트 왼쪽/도로 오른쪽, 좁은 분할에서는 텍스트 위/도로 아래.
- 배경은 밝은 회청색. 도로는 차분한 그라데이션, 얇은 차선/도로 가장자리, 민트색 대상 차로와 꺾인 연결 경로로 구분한다.
- 차량은 금속 질감의 후면 모습. 깊이와 방향은 고정하고 옆 차선으로만 이동한다. 사용자 요청한1초 이동/1.45초 반복을 유지한다.
- SDK는 안내의 표시/숨김과 연결 지점까지의 거리를 제공한다. 애니메이션은 도로 구조 설명 예시이며 현재 차로 인식이 아니다.
- 대기/통과/무효 위치에서는 도로와 차량이 모두 사라진다. 외부 기본 내비의 지도·위치 고정 문제는 이 UI 작업과 별도다.
- 각 단계마다 반복하던 앱 제목/상태/설명 카드와 큰 제어 버튼을 정리한다. GPS 시연 표시와 정차 제어는 별도 작은 헤더/하단에 남긴다.

## 성공 기준

1. 영상에서 직접 관찰한 원근 도로·후면 차량·차로 면 강조가 구현된다.
2. 차량은 회전하지 않고 고정된 화면 깊이에서 옆으로 이동한다. 빠른 반복 중 SDK 콜백이 와도 재시작하지 않는다.
3. 전체 화면/분할 화면 모두 안내 문장, 차량, 도로가 잘리지 않고 읽힌다. 통과 문구로 바뀌어도 안내 영역 크기가 흔들리지 않는다.
4. 대기/통과/STALE/무효 값에서 도로/차량이 표시되지 않는다. 실제 경로·차로 승인 수준은 유지한다.
5. APK 빌드/lint, 계측 반복/게이트 검사, 실제 SDK GPS 재생으로 확인하고 원본 실패 및 수정 후 증거를 함께 보존한다.
6. 실제 에뮬레이터 스크린샷과 정상 속도 영상을 보며 시각적 품질을 확인한다. 컴파일 성공만으로 디자인 검증을 대체하지 않는다.

## build-31 첫 시각 점검

빌드/lint 및 기존 반복/게이트·차량 계측8개 통과. cluster-sdk-demo-11 전체 화면에서 후면차량/원근도로/차로면을 확인했다. 영상 중 분할 전환 시 OS가 앱을 재생성해 잠시 스플래시가 노출되고 SDK세션이 재구독됐다. 입력65개 중57개 대응으로 통합검사는 FAIL로 보존한다(동작순서는 관측됨). split-layout.png는 로딩 중 캡처로 최종 레이아웃 증거가 아니다.

시각 검토에서 차량이 넓은 도로 대비 작게 느껴지고 진입로 경계가 옅었다. 최종 조정으로 차량 약17% 확대, 도로 경계 대비를 조금 강화한다. 분할 배치를 먼저 안정시킨 후 새 위치 세션으로 재검증한다.

## build-32 최종 시각 점검과 입력 주기 점검

차량 크기/대비와 레이어 단위 갱신을 반영한 빌드/lint 성공, 반복/게이트4개 재검사 통과. cluster-sdk-demo-12에서 안정된 분할 화면의 안내·후면 차량 반복·통과 숨김을 관찰했다. 그러나 입력65개 중55개만5m 이내 대응하여 전체 자동 검사 FAIL로 보존했다. SDK 콜백 간격 중앙값1061ms/최대2222ms/1200ms초과21건, 호스트 입력 중앙값1000ms였다.

검증 기준을 완화하지 않고 재생 도구에 interval-seconds 옵션을 추가했다(기본1초 동작 유지). 간격과 speed-mps를 곱해 좌표 간 거리를 만들므로 실제 재생 속도가 지정값과 일치한다. 구간 앞180m부터 통과 후600m까지 2초 간격/7.5m/s로 재실행한다. 앱의1초 이동/1.45초 반복과 실제 SDK콜백은 변경하지 않는다.

최종 cluster-sdk-cadence-13 PASS:2초 간격/7.5m/s/180~600m 구간에서 입력35개 전부5m 이내 대조, 서로 다른 SDK좌표29개, 안내33콜백. WAITING → GUIDANCE(239.993m) → PASSED(495.082m). 1Hz 입력을 모두 수신했다고 주장하지 않는다.

최종 정상 분할 시연 영상은 cluster-sdk-demo-12/cluster-guidance-preview.mp4(원본29~43초, 정상속도)다. 영상과 연속 프레임에서 방향 고정 후면차량·차로면·빠른 횡이동/재시작을 확인했다. 전체 화면은 cluster-sdk-cadence-13/guidance.png에서 최종 크기를 확인할 수 있다. 종료 후 cluster-preview-14는 구간300m의 가상 위치를 유지하는 화면 미리보기이며 통과 검사가 아니다. 기본 내비의 지도/위치 문제는 별도 미해결이다.

## build-33 클러스터 구성 명확화

사용자가 디지털 계기판(클러스터)의 느낌을 재차 명시했다. 정보 설명 패널 중심의 좌우 구성을 없애고, 모든 화면에서 도로/차량을 중앙에 크게 놓았다. 위치명과 ‘몇m 앞 · 본선 연결’ 한 줄만 위에서 보조한다. 장면 최대폭을900→1180dp로 넓혔으며 중복 설명을 줄였다. 실제 SDK gate와 차량1초 이동/1.45초 반복은 변경하지 않았다. 이번 검증은 화면/반복/표시 회귀와 고정 가상 위치 시연에 한정한다.

최종 build-33 빌드/lint 및 반복/게이트4개 검사 통과. cluster-centered-preview-15의 실제 SDK 입력300m에서 중앙 배치와 반복 화면을 확인했다. 차량/도로와 한 줄 안내가 잘리지 않는다. 이 기록은 위치 고정 미리보기이며 새 구간 통과 실측은 아니다.
