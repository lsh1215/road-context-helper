# 구간 설명 차량의 부드러운 이동

최신 UI 결정은 아래 build-29 정정 사항을 따른다.

2026-11-14. 사용자 요청: 차량과 경로선의 움직임을 더 매끄럽고 빠르게 보여준다.

## 변경과 성공 기준

1. GPS 갱신 순간 차량이 목적 위치로 순간 이동하지 않는다. 두 위치 사이에 실제 렌더된 중간 위치가 존재해야 한다.
2. 이동 중 다음 GPS가 오면 기존 위치와 속도를 이어받아 새 목표로 이동한다. 구간을 벗어나면 애니메이션 종료를 기다리지 않고 도로와 차량이 사라져야 한다.
3. 마지막으로 받은 진행률까지만 보간하고 멈춘다. 새 GPS 없이 반복 이동하거나 다음 구간까지 예측하지 않는다. 시간만으로 초기 정지 차량은 이동하지 않는다.
4. 차량과 분홍색 경로는 동일 곡선을 공유한다. 직선과 곡선의 접선 및 곡률을 연속으로 연결하고, 이동/회전에 소수점 좌표를 유지한다.
5. 정차 중 독립 가상 차량 예시는 5.5초에서 4초로 단축한다. 실제 SDK 시험은 GPS 재생을 15m/s에서 22.5m/s로 1.5배 높인다. 구간 감지 거리와 위치 판정을 조작하지 않는다.
6. 빌드/lint, 새 보간·재목표·숨김 계측 검사와 기존 차량 회귀, 실제 SDK GPS 시연을 통과한다. 기기에서 영상으로 경로와 회전을 확인한다.

## 구현

SDK가 제공한 설명용 진행률에 감쇠비1/stiffness100의 유한 spring 보간을 적용한다. 새 값이 도착해도 속도를 보존한다. 기존 정차 시연은 유한 시간 애니메이션을 유지한다. 도로 경로의 측면 이동을 5차 보간으로 바꾸어 접선/곡률의 급변을 줄이고, 같은 선형의 거리 기준 위치를 차량과 방향 화살표에 사용한다. 차량 배치는 정수 offset 대신 graphicsLayer의 소수점 이동과 회전을 사용한다.

이 보간은 그림을 부드럽게 보여주는 표시 처리이며 새 SDK 위치를 만들지 않는다. 구간 밖/무효 상태에서는 패널이 즉시 제거되어 진행 중 보간도 취소된다. 기본 내비 지도/위치 고정 문제는 별도 미해결 상태다.

## 검증 결과

- build-28: assembleDebug/assembleDebugAndroidTest/lintDebug성공。
- 구간 UI4개+기존 차량4개=8개 계측 테스트 통과(10.175초).
- context-smooth-06: PASS. 실제 Pleos SDK 좌표34개, 입력47개 중43개가5m 이내 일치. WAITING → GUIDANCE(247.566m) → PASSED(495.082m).
- 22.5m/s 시연의 안내 노출은 약11초(이전15m/s 약17초). 영상 속도를 바꾼 것이 아니라 가상 GPS 진행 속도를 변경했다.
- demo.mp4에 원본, motion-preview.mp4에 안내 전후24초를 정상 재생속도로 보존했다. 연속 프레임에서 같은 경로를 따라 차량 이동과 회전이 이어지는 것을 확인했다.
- 기본 내비 위치 고정은 별도 미해결이며, 이 검증은 우리 앱의 표시 개선과 GPS 구간 판정에 한정한다.

## build-29 사용자 피드백 반영

차량은 항상 전방(화면 위)을 향한다. 차선 변경 중에도 회전하지 않고 위치만 이동한다. 안내선은 직선 → 대각선 → 직선으로 명확하게 꺾이며 곡선을 넣지 않는다. 위 build-28의 곡률/회전 개선 방향을 대체한다. 위치 보간, 빠른 시연 속도, SDK 구간 진입/이탈 판정은 유지한다.

성공 기준은 차량이 모든 구간에서 같은 방향을 유지하고, 분홍 선의 두 꺾임이 직선으로 보이며, 구간 통과 후 안내가 사라지는 것이다. 기존 위치 보간 및 구간 표시 회귀와 실제 GPS 재생 영상으로 확인한다.

빌드/lint와 기존 화면 테스트8개는 통과했다. context-upright-07 짧은 시연은 화면상 방향 고정/직선 안내선/통과 후 숨김을 확인했지만 자동 GPS 검증은 FAIL로 보존한다. 입력26개 중5m 이내 대응23개(90% 기준 미달), GUIDANCE콜백9개(최소10개 미달)였다. WAITING → GUIDANCE(247.544m) → PASSED(495.082m) 전환 자체는 관측됐다. 검증 기준은 완화하지 않고 전체 구간/15m/s로 context-upright-08 회귀 검사를 수행한다. 기본 시연속도22.5m/s와 앱의 위치 보간은 변경하지 않았다.

context-upright-08 전체 구간 회귀 PASS. 서로 다른 SDK좌표52개, 입력65개 중60개가5m 이내 일치, GUIDANCE콜백17개. WAITING → GUIDANCE(239.993m) → PASSED(495.082m). 연속 영상 프레임에서 차선 이동 중 차량 방향 고정과 직선 안내선을 확인했다. 새 UI는 build-29로 설치되어 있다.

## build-30 빠른 반복 예시

사용자는 이동을 훨씬 빠르게 반복해서 보여 달라고 요청했다. 구간 안내의 차량 모형은 이제 GPS 진행률을 그대로 따라가는 위치 표시가 아니라 **1초 이동을 약1.45초 주기로 반복하는 설명 애니메이션**이다. GPS는 해당 구간 안내를 켜고 끄는 데 계속 사용한다. 새 위치가 도착해도 재생 주기는 초기화하지 않는다. 차량은 항상 전방을 향하며 안내선은 꺾인 직선이다.

이동1,000ms, 도착 정지200ms, 사라짐100ms, 숨긴 초기화50ms, 나타남100ms로 구성한다. 되돌아가는 차량을 그리지 않는다. 안내가 숨겨지거나 위치가 무효/오래된 상태가 되면 애니메이션도 제거한다. 새 안내 진입은 첫 장면에서 시작한다. 별도의 정차 가상 시연 모드는 기존 동작을 유지한다.

이 변경은 build-28/29의 ‘새 GPS가 없으면 차량도 멈춘다’는 표시 기준을 사용자 요청에 따라 대체한다. 위치 SDK 판정·실제 도로 검증 수준·기본 내비 문제 해결 여부를 바꾸지 않는다.

성공 기준: 첫 이동 약1초 내 완료, 새 GPS 없이 두 번째 이동 재생, 재생 중 GPS 갱신에도 리셋 없음, 구간 이탈/STALE 시 즉시 제거, 전방 방향/직선 안내선 유지. Compose 시계로 렌더된 차량 위치를 관측하고 실제 SDK 시연의 영상으로 반복을 확인한다.

계측 검사: 첫 실행은 반복 시계가 각 advanceTimeBy마다 프레임 경계로 올림되어 동일 위상 비교1건 실패(원본 ui-first.txt 보존). 검사 시계만 정확한 경과 시간으로 수정했다. 두 번째 실행에서 새 반복/게이트4개는 모두 통과했으나 기존 정차 시연1건은 Compose 계층이 없어 관측 실패(ui-second.txt). 해당1건을 독립 재실행해 통과(ui-targeted.txt). 총8개 고유 검사에 통과 증거가 있으며 한 번의8개 전부 통과 실행으로 표현하지 않는다. 제품 코드는 재검사 중 변경하지 않았다.

context-loop-09 영상에서1초 이동/숨김/출발 위치 재등장/반복을 확인했다. 구간 통과 후 UI는 사라졌다. GPS 동작 순서는 PASS지만 입력39개 중35개(89.7%)만5m 이내 대조되어 전체 자동 검증은 FAIL로 보존했다. 검증 기준이나 제품을 바꾸지 않고 표준 전체 구간 context-loop-10을 재실행한다. repeat-preview.mp4는 원본17~29초를 정상 속도로 자른 영상이다.

context-loop-10 표준 전체 구간 PASS. 입력65개 중60개가5m 이내 대조, 실제 SDK 이동좌표52개, GUIDANCE15콜백. WAITING → GUIDANCE(254.971m) → PASSED(495.082m). build-30 설치 상태로 검증을 마쳤다.
