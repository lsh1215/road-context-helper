Navigation companion: installed public API evidence
Checked 2026-11-14; read-only investigation, no emulator/build/source/config changes.

판정
1. NaviHelper3.0.5의 외부 공개 진입점에 split-window/overlay/custom View/marker/layer API는 없다.
   getInternalApi()는 JVM public으로 보이지만 공식 공개 API 목록에는 없으며 InternalApi/PrivateApi 영역은 사용 허용으로 해석하지 않았다.
   따라서 '없다'는 이 버전의 공개 계약에 대한 결론이며 Pleos 시스템 전체 기능 부재라는 뜻은 아니다.
2. NAVI_CUSTOM_MAP 권한이 달린 외부 메서드는 requestNavigationScreen(NavigationScreenRequest)이다.
   navi-data3.0.4의 요청 종류: Foreground, MoveToCurrentLocationOnMap, SearchPlace(keyword),
   POIDetailPopup(poiId, poiProvider), OverviewRoute(RouteOverviewShowInfo), Settings, EditRoute,
   RouteOptionList, RecentDestinations, FavoriteMain, AddHomeFavorite, AddWorkFavorite, NearbyChargingStations.
   이는 내비가 정의한 화면 요청이다. POIDetailPopup의 이름을 임의 안내카드/Compose UI 삽입 API로 해석할 수 없다.
   공개 계약에서 임의 marker/layer 삽입도 확인하지 못했다. 권한 이름만으로 custom map UI를 약속하지 않는다.
3. 근접 감지는 공개 API로 가능하다: FusedLocation.addProximityAlert(request, listener).
   request는 latitude/longitude/radiusMeters/Set<ENTER,EXIT>, listener는 onRegistered(alertId),
   onTransition(ProximityAlertEvent(alertId,transition)), onError(Exception).
   removeProximityAlert(alertId)로 해제. javap -v로 두 메서드의 FUSED_LOCATION RequiresPermission 확인.
   공개 DTO는 원형 영역 진입/이탈이며 차로, 진행방향, 경로 소속, 합류 구조를 판정하는 입력이 없다.
   검증된 도로 데이터/경로/heading으로 별도 필터링이 필요하다. 최대 등록 수, background 지속,
   프로세스 사망 후 복원, callback 지연 보장, 각 반경의 정확도는 이 조사에서 확인하지 못했다.
   기존 실험은 registerFusedLocationCallback 위치 갱신 성공이며 proximity callback 실측은 아직 없다.
4. 현재 제품은 MainActivity resizeableActivity=true, distractionOptimized=true이다.
   이는 분할 화면에 대응할 준비이지 내비와 자동으로 나란히 배치할 권한/성공 증거가 아니다.
   Android에는 FLAG_ACTIVITY_LAUNCH_ADJACENT|FLAG_ACTIVITY_NEW_TASK가 있지만 제조사 정책에 따라 다르며
   Pleos 런처가 이 조합을 지원하는지 별도 공식 확인/기기 시험이 필요하다. 이번에는 실행하지 않았다.
5. 현재 제품은 MainActivity.onStart에서 model.start, onStop에서 model.stop을 호출한다.
   RoadViewModel.stop은 ticker 중지, livePresentation 제거, reader.close/null을 수행한다.
   manifest에 Service/Receiver, SYSTEM_ALERT_WINDOW, FOREGROUND_SERVICE, POST_NOTIFICATIONS가 없다.
   따라서 현재는 보이는 앱 안에서 조건부 카드를 표시하는 구조이며, 숨겨진 앱이 합류 때 자동 전면 등장하는 구조가 아니다.
   분할 화면에서 계속 visible/STARTED이면 수신을 유지할 수 있는 Android 생명주기 구조이나 Pleos 실측은 미완료.
6. 근접 event 수신과 UI 전면 등장 권한은 별개다. addProximityAlert는 앱 화면을 자동 띄우지 않는다.
   showLocationAccessBlockedPopup은 SDK 위치 접근 차단 안내용이며 임의 팝업 API가 아니다.
   백그라운드 Activity 실행에는 Android 제한과 차량 UI 정책 검토가 필요하다. 알림/서비스/overlay를 구현·승인됐다고 가정하지 않는다.

현재 제품에서 가장 근거 있는 선택: 사용자가 내비와 보조 앱을 나란히 열 수 있는 런처 동작을 먼저 검증하고,
보조 앱 내부 안내는 접근할 때만 활성화한다. 분할 성공이 아직 증명되지 않았으므로 이 선택도 다음 검증안이다.
완전히 숨었다가 합류 때 자동 팝업하는 안은 background 수신·표시 권한·주행 UI 정책이 별도 미해결이다.
