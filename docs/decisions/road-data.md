# 실제 도로 구조 자료 반입 결정

확인일: 2026-11-14 / 상태: 승인 가능한 합류 원자료 미확보, AC-20 미통과 (공개 샘플 ZIP 1건은 별도 검수 보류)

## 결정

실제 도로 자동 안내 카탈로그는 빈 배열로 시작한다. 시연 geometry를 실제 장소의 geometry로 채우지 않는다. 원본을 확보한 뒤 topology·방향·제작일·변환 좌표계·이용 조건을 검수하고 승인한 구간만 활성화한다.

## 이번에 확인한 사실

1. [공공데이터포털 정밀도로지도](https://www.data.go.kr/data/15059912/fileData.do)의 실제 화면에서 SHP 벡터 데이터, 무료, 공공누리 제1유형(출처표시)을 확인했다. 페이지 표시 파일명은 `국토교통부 국토지리정보원_정밀도로지도_20250430`, 수정일은 2025-06-23이다. 이 날짜는 특정 구간 원자료의 최신 측량일을 보증하지 않는다.
2. [국토정보플랫폼 정밀도로지도](https://map.ngii.go.kr/ms/pblictn/preciseRoadMap.do)에 벡터데이터·점군데이터 선택 다운로드가 있다. 벡터 목록에 서울특별시_용산구, 서울특별시_성북구, 서울특별시도 여러 노선, 서울특별시도_북부간선도로, 동해선_남포항IC가 실제로 표시된다. 목록에 있다는 사실과 사용자의 합류 구간이 수록되었다는 사실은 다르다.
3. `동해선_남포항IC` 벡터 항목을 선택한 뒤 `선택다운로드`를 누르자 정부 통합로그인 화면으로 이동했다. 로그인은 모바일 신분증, 간편인증, 국토정보플랫폼 아이디 방식을 제공한다. 이 시험은 다운로드 경로 확인일 뿐 실제 구간 선택을 확정한 것이 아니다.
4. NGII의 실제 SHP/DBF/PRJ 원본은 아직 받지 않았다. 따라서 NGII 원본 필드명, 차로 연결 관계, 합류 끝점 좌표, 구간 제작일을 확인하지 못했다. 아래 추가 조사에서 별도 기관의 공개 샘플은 확보했지만 자동 안내로 승인한 실제 구간은 여전히 0개다.

증거는 `data/evidence/`에 있다. 로그인 화면 증거에 일회성 인증 transaction URL은 저장하지 않았다.

## 대안 조사와 채택하지 않은 이유

- [국토부/국토지리정보원 정밀도로지도 소개](https://www.innovation.go.kr/ucms/bbs/B0000037/view.do?menuNo=300192&nttId=14100&pageIndex=1)는 무상 제공의 근거이지만 최신 개별 구간 geometry 다운로드 파일이 아니다.
- [서울 실시간 도시데이터](https://data.seoul.go.kr/dataVisual/seoul/guide.do)는 도로 소통·사고/통제 정보를 설명한다. 이번 조사에서 차로 중심선 연결 topology가 제공된다는 증거는 찾지 못했으므로 합류 끝점 자료의 대체로 쓰지 않는다.
- [스마트서울맵](https://map.seoul.go.kr/smgis/webs/main/main.do?mode=seoulMapSearch)의 일반 도로구간 표시만으로 차로 종료·연결 구조를 추론하지 않는다.
- [AI Hub 정적객체 인지/갱신 자료](https://www.aihub.or.kr/aihubdata/data/view.do?aihubDataSe=ty&currMenu=&dataSetSn=71583&topMenu=)는 정적 객체 이미지·라이다 학습 데이터 설명이며, 바로 배포할 최신 합류 도로 topology를 확보한 것은 아니다.
- 공개 연구 논문은 A1_NODE/A2_LINK/B2_SURFACELINEMARK 등 자료 구조를 설명하지만 원자료·구간 최신성·재배포 근거를 대신하지 않는다. 검색에서 확인되지 않은 GitHub 샘플이나 알 수 없는 파일 URL을 추정해 다운로드하지 않았다.

대안이 절대 존재하지 않는다고 결론내리는 것은 아니다. 현재 확보한 공식 접근 경로 중 실제 벡터를 받는 가장 직접적인 경로는 NGII 로그인 후 다운로드다.

## 사용자에게 필요한 최소 행동

1. [국토정보플랫폼 정밀도로지도](https://map.ngii.go.kr/ms/pblictn/preciseRoadMap.do)에 접속해 본인의 계정/간편인증으로 로그인한다. 비밀번호·인증코드는 채팅에 전달하지 않는다.
2. 같은 브라우저 세션에서 `벡터데이터`를 선택하고 필요한 구간을 선택한다. 첫 다운로드 가능성 시험은 `동해선_남포항IC`; 실제 사용자 경로 자료 탐색은 용산구/성북구 및 해당 노선 coverage를 보고 결정한다.
3. `선택다운로드`를 누른다. 포털이 별도 전송 프로그램을 요구하면 해당 OS 지원 여부를 확인해야 한다. 아직 로그인 후 전송 단계까지 확인한 것은 아니다.
4. 원본 zip 또는 SHP+DBF+SHX+PRJ 및 포함 메타데이터를 프로젝트 `data/incoming/`에 놓는다. 원본 이용 안내 파일도 함께 보존한다. 사용자가 원본을 놓으면 다음 단계에서 파싱·검수·변환을 계속한다.

2026-11-14 사용자는 지금 로그인할 수 없다고 답했다. 인증 재요청은 하지 않는다. ego lite task space `road-context-development`(144)를 다시 인수해 로그인되지 않은 최종 화면을 확인한 뒤 `task.finish({keep:[]})`로 정상 종료했다. 위 단계는 추후 사용자가 직접 재개할 때 참고할 절차이며 현재 행동 요청이 아니다. 브라우저 업그레이드 알림(0.6.2.9)은 적용하지 않았다.

## 다운로드 후 처리

- 파일 sha256·원본 출처·노선명·정확한 데이터 버전을 기록한다.
- `.prj`와 metadata로 CRS를 확인하고 WGS84 변환을 검증한다. 좌표 숫자만 보고 CRS를 추정하지 않는다.
- SHP의 필드를 직접 열어 연결 node/link 관계와 선 종류를 확인한다. 현재 공개 문서의 필드 이름을 원본 확인 없이 hard-code하지 않는다.
- 최소 1개 합류 후보를 원본 topology와 별도 확인 자료로 교차 검토한다. 두 진입 링크가 한 점에서 만난다는 이유만으로 '차로 끝까지 이어짐'을 확정하지 않는다.
- 검수 전 catalog 상태는 빈 배열 유지. 승인한 구간도 만료 시 비활성화한다.


## S0 보완: 후보 도로의 완전성 검증

독립 리뷰에서 지원 구간 중심선만 매칭하면 미지원 인접도로가 누락되어 거짓 단일 후보가 될 수 있음을 확인했다. runtime schema 2는 `matchingCoverage`와 모든 경쟁도로를 담은 `candidateRoads`를 요구한다. 자료의 범위·제작/검수일·해시·출처·전체 범위/평행 도로/입체 도로/램프/교차로 확인 기록이 필요하다. 검색 반경과 위치 오차를 포함한 전체 영역이 검수 범위 안에 들어올 때만 실제 매칭할 수 있다. 형식 검증이 원자료의 완전성을 증명하는 것은 아니다.

현재는 이런 원자료도 확보되지 않았다. 실제 카탈로그는 schema 2의 빈 목록이며 기존 schema 1은 빈 목록만 호환 허용한다. `mergeSide`는 **본선에 대해 진입 차로가 놓인 쪽**으로 고정한다. RIGHT면 우측 진입 차로가 왼쪽으로 합류하는 구조이고, 현재 차량 차로/즉시 조작 지시가 아니다.

### 다운로드에 성공한 GITC 샘플의 구체 검수

- [원본 ZIP](https://gitc.or.kr/uploads/board/table204/A_653b58f001829/20231027653b58f001f19.zip)은 `data/incoming/gitc-gyeongsan-20231027.zip`에 격리했다. `incoming/`은 Git 제외 경로다. 공개 게시 파일을 분석 목적으로 읽었으며 배포 승인으로 취급하지 않는다.
- SHA-256: `4d2ae3d0e6f45836f072882057ad83b27977c357dc9225a72f641a1fb5879e68`. 재현 가능한 필드/크기/좌표계 검사 결과는 `data/evidence/gitc-gyeongsan-intake-inspection.json`이다.
- 세 레이어를 실제 열었다. LANE은 PolyLineZ 47개, LINK는 PolyLineZ 12개, STOPLANE은 PolygonZ 10개다. LINK 필드는 `NAME`, `LANE_ID`, `LANE_KIND`, `LANE_MAIN`뿐이다. 전후 연결 ID나 명시적인 진행 방향 필드는 없으므로 정점 순서를 실제 진행 방향으로 가정하지 않는다.
- `.prj`는 WGS84 / UTM zone 52N을 명시한다(중앙자오선 129°, 축척 0.9996, false easting 500000m). 이는 WGS84 위경도 좌표가 아니다. 이번에는 변환하거나 runtime centerline을 생성하지 않았다.
- 페이지 표기는 `update_20231027`인데 파일명과 XML 생성 이력은 `20220809`다. 현재 도로 최신성을 증명하지 못한다. `END LANE`이라는 객체 명칭만으로 진입차로 종료를 뜻한다고 해석하지 않는다.
- 공개 페이지와 ZIP에서 앱의 파생 이용/재배포를 허용하는 명시적인 라이선스를 찾지 못했다. 공개 다운로드 가능성과 배포 허용은 별개다. 주변 평행·입체·램프·교차도로 전체를 포함했다는 coverage 검수 근거도 없다.
- 따라서 상태는 **샘플 원자료 확보 / 합류 topology·방향·최신성·coverage·이용조건 미승인**이다. 이 파일을 받았다고 AC-20을 통과시키지 않는다.

이번 조사 결과는 '공식 원자료를 전혀 구할 수 없다'가 아니다. 로그인 없는 공식 SHP 샘플은 실제로 확보했지만, 이 앱이 요구하는 검증된 합류 구조와 경쟁도로 coverage를 모두 충족하는 자료는 확보하지 못했다. 후속 경로는 GITC에 자료 사전/이용조건/업데이트·범위 확인, 새만금 센터의 공개 배포 조건 확인, 또는 사용자가 나중에 NGII 자료를 제공하는 것이다. 외부 문의는 보내지 않았다. OSM/일반 중심선/POI로 검수 빈칸을 채우지 않았다.
