> 사용자 정정으로 차별성 검증을 우선한다. Y자 분기는 build-35에서 제거했고 나머지 사례도 Pleos 미제공 기능으로 확인되지 않았다. [필수 채택 기준](differentiation-gate.md)을 먼저 따른다. 아래는 build-34 시연 구현 당시의 기록이다.

# 도로 상황별 클러스터 데모

사용자가 기존 본선 연결 외에도 합류 직후 여러 차로를 바꿔 가까운 진출로에 대비하는 상황을 요청했다. 네 가지 가상 사례를 정차 중 선택하거나 전체 순회로 볼 수 있게 한다. 기존 SDK GPS 시험의 표시/숨김 판정은 유지한다.

## 사례

| 상황 | 설명 목적 | 도로와 차량 표현 |
|---|---|---|
| 본선 연결 | 진입 차로 끝과 본선 연결을 미리 이해 | 오른쪽 진입 차로에서 왼쪽으로 한 차로 이동 |
| 합류 후 가까운 진출 | 합류 전에 다음 진출과 필요한 준비를 알림 | 왼쪽 합류·4개 본선 차로·오른쪽 진출, 세 차로 순차 이동 |
| Y자 분기 | 분기점 전에 진행 방향 인지 | 분리되는 두 갈래 중 왼쪽을 강조 |
| 진출 전용 차로 | 현재 쪽 차로가 본선에서 빠지는 구조 인지 | 오른쪽 진출 분리와 왼쪽 본선 유지 |

300m/200m/100m는 시연용 거리다. 실제 도로 조사 결과나 SDK 차로 추정으로 취급하지 않는다. 가까운 진출은 급한 차로 변경을 지시하지 않고 여유가 없으면 다음 경로 이용을 안내한다.

## 성공 기준

1. 네 사례를 사용자가 직접 선택할 수 있고 이름뿐 아니라 도로 구조·경로·차량 이동이 다르다.
2. 기본 화면은 새 요청인 가까운 진출이다. 차량은 전방을 향한 상태로 세 차로를 순차 이동한다. 각 이동 750ms와 중간 150ms 정지, 전체 2.85초 주기로 반복한다.
3. 각 사례의 미리보기/구간 안내/통과를 전환할 수 있다. 통과 시 도로와 차량이 사라진다.
4. 전체 순회는 각 사례의 미리보기→안내→통과를 반복한다. 개별 선택은 순회를 중단한다.
5. 주행 제한 또는 정책 미확인 상태에서는 가상 그림과 조작을 숨긴다. 정차 상태에서만 다시 표시한다.
6. 원래 SDK 본선 연결의 1.45초 반복과 GPS 유효성·표시/숨김 테스트가 유지된다.
7. 실제 전용 에뮬레이터에 설치해 네 도로 형태와 조작을 확인하고 증거를 보존한다.

일시정지는 차량을 시작 위치의 정지 예시로 바꾸며 재생 시 새 주기를 시작한다. 새로운 사례는 가상 UI 시연이며 실제 도로 데이터 등록·자동 사례 분류·기본 내비 동기 이동을 완료했다고 간주하지 않는다.

## 검증

새 계측 검사: 네 사례 선택과 의미, 미리보기/통과/재진입, 제한 시 숨김, 세 번의 이동과 중간 정지·전방 고정·일시정지. 기존 ContextRoadPanelTest와 RoadVehicleIllustrationTest를 회귀 대상으로 실행한다. 결과와 실제 시연은 verification/runs/build-34 및 cluster-gallery-16에 기록한다.
